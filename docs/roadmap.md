# 로드맵

제출물은 발표자료(pptx)와 구현물 zip이다. 팀은 7명이고 검증은 최소 5회 요청해야 한다. 제출 마감일은 아직 확인하지 못했다.

## 현재 상태 (2026-11-24 밤)

- 시나리오 S1~S7 코드 완성, 실험 결과 없음
- 11/24에 `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`의 하루 한도(500회)를 모두 썼고 한국 시간 11/25 오후 5시쯤 초기화된다
- 필요한 호출: 3.5-lite 약 240회(S1, S3, S7), 3.1-lite 약 440회(S2, S4, S5)와 S6 약 110회

## 남은 단계

1. Gemini 실험 실행 (병렬 두 줄, 약 40분)
2. 결과 점검, 필요하면 보정
3. 검증 5단계 `src/verify.py`
   - V1 데이터·라벨 (작성됨)
   - V2 현상 재현
   - V3 채점기 표본 검수
   - V4 완화 효과와 부작용
   - V5 캐시 재실행, 슬라이드 수치 대조, zip 비밀 검사
4. `slides/build_slides.py`로 pptx 생성, PDF로 내보내 눈으로 검수
5. README 보완, 구현물 zip 패키징

## 1차 회의 안건

1. 검증 5회 요청을 누가 맡을지
2. 발표자료 분담 (시나리오별로 나눌지)
3. 제출 마감일
4. 팀원 이름과 역할을 README, 슬라이드에 넣을 것
5. 유료 Gemini 키를 쓸지. 쓰면 뺀 조건(다수결, 자기 검증, CoVe, 질문 중립화)을 되살릴 수 있다

## 알려진 문제

- 실험 전 점검 로그에서 S2가 `KeyError: 'rep'`로 멈춘 기록이 있다. Gemini 응답이 빈 상태에서 패키지가 0개일 때 생긴 것으로 보이며, 실제 응답이 들어온 뒤 다시 확인한다.
